Bipartite graph layout research prototype

二つの画面をまたぐ
二部グラフの空間配置

集合Aと集合Bを別々のグリッド画面に表示し、ある要素を選択して反対側へ遷移したとき、その隣接要素が元の選択位置の近くに現れるように、両側の配置を同時に最適化します。

数理モデルを読む 最適化手順を見る

選択した頂点の位置を、反対側の隣接頂点群に対する空間的な参照点として用います。

Problem

問題設定

二部グラフ G = (A ∪ B, E) を対象とします。画面には一度に集合Aまたは集合Bの一方だけが表示され、両画面は同じ論理座標系を共有します。

A

集合Aの画面

頂点 a をタップすると集合Bへ切り替わります。a と辺で接続された頂点を、a が表示されていた論理座標の周辺へ集めます。

B

集合Bの画面

逆方向も同一です。頂点 b の隣接頂点を、集合A側で同じ位置の周辺へ配置します。

T

トーラスグリッド

左右端、上下端を接合します。周期境界をまたぐ近接関係は、ユーザーが明示的にスクロールして確認します。

Mathematical model

トーラス上のマンハッタン距離

横幅 W、高さ H のグリッドを ZW × ZH とみなし、各軸で周期境界を考慮した最短差を求めます。

δx = min(|x₁ − x₂|, W − |x₁ − x₂|),　δy = min(|y₁ − y₂|, H − |y₁ − y₂|)
dM(p, q) = δx + δy 上下左右の1マス移動を1距離単位とするため、斜め位置は2、横1・縦2の位置は3になります。

配置最適化では、生の距離ではなく距離の指数 p を変えたコストも扱います。

Lp(x, y) = Σ(a,b)∈E wab · dM(x(a), y(b))p,　1.0 ≤ p ≤ 2.0 p = 1.0 は総移動マス数を直接評価し、p を大きくすると遠距離の辺をより強く罰します。

指数を変える意味

  • p = 1.0: 平均的な距離の短縮を優先します。
  • 1.0 < p < 2.0: 平均距離と長距離辺の抑制を連続的に調整します。
  • p = 2.0: 少数の長距離辺に大きなペナルティを与えます。
指数を変更すると目的関数自体が変わるため、表示上の数値を再計算するだけではなく、同じグラフに対して配置を再最適化します。

Optimization

交互割当による最適化

通常の算術重心は周期境界およびマンハッタン距離に対して直接利用しません。各頂点を各候補セルへ配置した場合のコストを総当たりで計算し、線形割当問題として解きます。

1

集合Bを固定

各 a ∈ A と各セル s に対して、a の全隣接頂点までの重み付き dMp の和 CAa,s を計算します。

2

集合Aを割当

コスト行列 CA にHungarian algorithmを適用し、100頂点を100セルへ重複なく配置します。

3

方向を反転

集合Aを固定して集合Bを同様に割り当て、目的関数が改善しなくなるまで交互に反復します。

CAa,s = Σb∈N(a) wab · dM(s, y(b))p

辺重み

高次数頂点㇠けが目的関数を支配しないよう、各頂点をタップしたときの平均隣接距離に対応する次数正規化重みを利用できます。

収束と局所解

片側を固定した各更新は割当問題の厳密解なので、目的関数は増加しません。ただし全体は非凸であり、最終結果は初期配置に依存します。

Interface model

周期表示とスクロール

論理的には10×10の100セルですが、表示時には同じ配置を上下左右へ周期的に複製します。ユーザーは周期平面をスクロールし、境界の反対側にある近傍を自分で表示領域へ移動します。

  • 集合Aと集合Bは共通のスクロール座標を保持します。
  • 画面切替時に自動センタリングしません。
  • 周期複製をタップても同じ論理頂点を選択します。
  • 選択位置と隣接頂点を反対側画面で強調します。

Limitations

解釈上の注意

完全な近接性は保証できない

完全二部グラフや高密度グラフでは、すべてのタップについて全隣接頂点を近傍へ配置することは不可能です。

トーラス距離と見かけの距離

周期境界をまたぐ二要素は数学的には近くても、現在の矩形ビューポートでは離れて見えることがあります。

指数は設計上の選好

大きな指数が常に優れているわけではありません。平均性能と最悪距離のどちらを重視するかによって選択します。
