Algorithm documentation

二部グラフの
二画面グリッド配置

一方の集合の頂点をタップしてもう一方の集合へ切り替えたとき、隣接頂点がタップ位置の近くに現れるように、二つの配置を同時に最適化する問題を定式化します。

対象

  • 二部グラフ G=(A∪B,E)
  • AとBを別々の画面に表示
  • 各画面は有限グリッド
  • 各頂点は一意のセルを占有
  • 両画面は同じ論理座標系を共有

1. Problem

問題設定

二部グラフを G=(A∪B,E) とします。AとBの頂点数はデモではそれぞれ100です。画面には一度に一方の集合だけを表示します。

A

AからBへの遷移

a∈AをタップするとB画面へ切り替わり、N(a)={b∈B|(a,b)∈E} が元のタップ位置付近に現れることを目標とします。

B

BからAへの遷移

b∈Bをタップした場合も対称に、N(b)に属するA頂点が元のタップ位置付近に現れることを目標とします。

C

競合

複数頂点が同じ理想位置を要求しても、同じ画面内ではセルを共有できません。そのため全体として一対一割当を解きます。

2. Coordinates

配置と共有座標

A画面のセル集合をPA、B画面のセル集合をPBとし、配置をx:A→PA、y:B→PBとします。各写像は単射です。10×10で100頂点なら全単射になります。

x(a)=(xa,ya),　y(b)=(xb,yb)AとBは異なる画面なので、x(a)=y(b)は許されます。同じ座標であることが、遷移前後の画面位置が一致することを意味します。

3. Edge weights

次数による偏りを抑える辺重み

全辺を同じ重みで評価すると、高次数頂点が目的関数を強く支配します。各頂点を同程度の頻度でタップすると仮定する場合、各タップにおける平均隣接距離を評価する重みが自然です。

wab = λ pa/deg(a) + (1−λ) qb/deg(b)paとqbはタップ確率、λは二方向の重要度です。情報がなければ一様確率とλ=1/2を利用できます。
孤立頂点は距離制約を持ちません。ID順、属性順、前回位置からの移動量など、別の規則で配置する必要があります。

4. Distance models

三つの距離モデル

平面ユークリッド距離

d²=(Δx)²+(Δy)²。最初のデモで使用し、通常の重心による簡略化が可能です。

トーラス・ユークリッド距離

各軸の差を周期境界をまたぐ最短差へ置き換えます。右端と左端、上端と下端が隣接します。

トーラス・マンハッタン距離

dM=δx+δy。上下左右の一マス移動を1とし、斜め位置は2です。

δx=min(|x₁−x₂|, W−|x₁−x₂|),　δy=min(|y₁−y₂|, H−|y₁−y₂|)
dT,2²=δx²+δy²,　dT,1=δx+δy

マンハッタン距離は、表示グリッドを上下左右の辺で接続したグラフとみなしたときの最短経路長です。10×10トーラスでは最大距離は10です。

5. Objective

指数付き目的関数

Lp(x,y)=Σ(a,b)∈Ewabd(x(a),y(b))pデモではpを1.0から2.0まで0.1刻みで変更できます。

p=1

総距離を直接最小化します。多数の辺の平均的な改善を重視し、少数の長距離辺に対するペナルティは比較的弱い設定です。

p>1

凸増加するコストとなり、遠距離の辺を相対的に強く罰します。p=2では距離2、3、4のコストは4、9、16です。

異なる指数の目的関数値をそのまま大小比較することには注意が必要です。指数ごとの配置比較では、生の平均距離、最大距離、距離分布も併記します。

6. Optimization

片側を固定した交互最適化

両配置を同時に最適化すると組合せ数が極めて大きくなります。一方を固定すると、他方の各頂点を各セルへ置くコストが計算でき、線形割当問題になります。

1

初期配置を用意

AとBの100頂点を、それぞれ100セルへランダムまたはスペクトル的に一対一配置します。

2

Bを固定してAのコスト行列を作る

CAa,s=Σb∈N(a)wabd(s,y(b))p
3

Aを一対一割当

CAをHungarian algorithmへ渡し、Aの全頂点をセルへ重複なく割り当てます。

4

Aを固定してBを更新

CBb,s=Σa∈N(b)wabd(s,x(a))p
5

反復

目的関数が改善しなくなるか、指定反復回数へ達するまでA更新とB更新を交互に行います。

positionsA, positionsB = initial_assignment()
repeat:
    costA[a][cell] = sum(weight(a,b) * distance(cell, positionsB[b]) ** p)
    candidateA = hungarian(costA)

    costB[b][cell] = sum(weight(a,b) * distance(cell, candidateA[a]) ** p)
    candidateB = hungarian(costB)

    accept candidateA, candidateB only when the objective improves

7. Assignment

Hungarian algorithmを使う理由

各頂点には100個の候補セルがありますが、一つのセルは一頂点だけに割り当てられます。各頂点が独立に最小コストセルを選ぶと衝突するため、全体のコスト和を最小化する完全マッチングが必要です。

項目意味
行配置する側の頂点
列候補グリッドセル
要素 C[i][j]頂点iをセルjへ置いた場合の隣接距離コスト
解行と列を重複なく対応させる最小コスト割当

100×100の割当では、典型的な計算量O(100³)はブラウザ上でも実用的です。

8. Convergence

単調改善と局所最適

片側を固定した更新は、その側についての最適な割当を求めるため、受理条件を正しく実装すれば目的関数は増加しません。ただし二つの側を合わせた問題は非凸であり、大域的最適解は保証されません。

同率解

トーラスの平行移動対称性などにより、同じコストを持つ配置が多数存在します。ID順タイブレークや前回位置への弱い正則化を利用できます。

周期

同じ値の配置間を往復しないよう、厳密に改善した場合だけ更新するか、過去の配置ハッシュを記録します。

複数初期値

乱数シードや回転・反転した初期配置を複数試し、最終目的関数が最良の結果を採用します。

9. Initialization

初期配置

デモでは再現性を優先し、シード付き疑似乱数による置換を使用します。より高品質な初期値としては、正規化二部隣接行列の特異値分解を使うスペクトル埋め込みが考えられます。

S=DA−1/2 M DB−1/2=UΣVᵀ非自明な特異ベクトルを二次元座標として用い、その後グリッドセルへの割当を解きます。

10. Interface implementation

トーラス表示とスクロール

論理的な配置は10×10ですが、画面には同じ配置を3×3に複製して描画します。中央コピーから周辺コピーへスクロールしたら、見た目を変えずに中央へ座標を戻すことで、周期的なスクロールを実現できます。

  • A画面とB画面は同じスクロール位置を共有します。
  • タップによる画面切替時には自動センタリングしません。
  • 周期複製は同じ論理頂点IDを参照します。
  • 境界をまたぐ近傍は、利用者が明示的にスクロールして確認します。
  • タップした位置と隣接頂点をCSSクラスで強調します。
数学的な距離と現在の矩形ビューポート上の見かけの距離は一致しない場合があります。この設計では、それを自動的に補正せず、トーラスをスクロール可能な空間として利用者へ提示します。

11. Complexity

計算量

n=|A|=|B|、m=|E|、セル数nとします。候補セルごとに隣接辺を走査する素朴なコスト行列生成はO(nm)、Hungarian algorithmはO(n³)です。

処理計算量100頂点での目安
距離表の事前計算O(n²)10,000組
片側コスト行列O(nm)密グラフでも約100万加算
片側割当O(n³)約100万オーダー
交互反復反復数×上記数回から十数回

12. Limitations

限界と拡張

不可能な要求

完全二部グラフでは、すべての反対側頂点をすべてのタップ位置の近くへ同時に置くことはできません。得られるのは妥協解です。

高密度グラフ

グラフが密になるほど位置を区別する情報が減ります。カテゴリや時間など外部属性を副目的として追加できます。

安定性

グラフ更新ごとに再配置すると空間記憶が失われます。前回位置からの移動コストを弱く追加する方法があります。
